# Deployment Guide for Render.com

This guide will walk you through deploying the Gaayatri Project to Render.com.

⚠️ **Important**: First deployment with ML dependencies takes **10-15 minutes**. See [RENDER_TROUBLESHOOTING.md](RENDER_TROUBLESHOOTING.md) if you encounter issues.

## Prerequisites

1. A [Render.com](https://render.com) account (free tier available)
2. A [Groq API key](https://console.groq.com) for the AI chatbot functionality
3. Your code pushed to GitHub

## Quick Start

**For fastest deployment** (2-3 minutes), see [Fast Deployment Option](#fast-deployment-option) below.

## Deployment Steps

### Step 1: Prepare Your Render Account

1. Sign up or log in to [Render.com](https://dashboard.render.com)
2. Connect your GitHub account to Render if you haven't already

### Step 2: Deploy Using render.yaml (Recommended)

The repository includes a `render.yaml` file that automates the deployment:

1. In your Render dashboard, click **"New +"** → **"Blueprint"**
2. Select **"Connect a repository"**
3. Choose the `miru4128/gaayatri_project` repository
4. Render will automatically detect the `render.yaml` file
5. Review the services that will be created:
   - `gaayatri-db`: PostgreSQL database (free tier)
   - `gaayatri-app`: Web service running your Django app

⏱️ **Expected build time**: 
- First deployment: 10-15 minutes (downloading ML libraries: torch ~800MB)
- Subsequent deployments: 3-5 minutes (cached dependencies)
- **Don't panic if it seems slow** - large ML dependencies take time!

### Step 3: Configure Environment Variables

Render will automatically set most variables from `render.yaml`, but you need to add the chatbot API key:

1. Go to your web service in the Render dashboard
2. Navigate to **"Environment"** tab
3. Add the following environment variables:

#### Required Variables:
```
CHATBOT_API_KEY=<your-groq-api-key>
```

#### Optional Variables (already set by render.yaml):
- `PYTHON_VERSION=3.12`
- `DJANGO_SETTINGS_MODULE=gaayatri_project.settings`
- `DJANGO_SECRET_KEY` (auto-generated by Render)
- `DEBUG=False`
- `DATABASE_URL` (auto-configured from database)

#### Additional Optional Variables:
```
CHATBOT_MODEL=llama-3.1-8b-instant
CHATBOT_PROVIDER=groq
CHATBOT_EMBED_MODEL=all-MiniLM-L6-v2
ALLOWED_SIMILARITY=0.65
HUGGINGFACE_API_TOKEN=<optional-hf-token>
```

### Step 4: Wait for Deployment

1. Render will automatically:
   - Install Python dependencies from `requirements.txt`
   - Run database migrations (`python manage.py migrate`)
   - Collect static files (`python manage.py collectstatic`)
   - Start the application with Gunicorn

2. Monitor the build logs in the Render dashboard
3. First deployment typically takes 5-10 minutes due to:
   - Installing PyTorch (large dependency for sentence-transformers)
   - Downloading AI model weights

### Step 5: Create a Superuser

After deployment, you need to create an admin user:

1. In Render dashboard, go to your web service
2. Click the **"Shell"** tab to open a terminal
3. Run:
```bash
python manage.py createsuperuser
```
4. Follow the prompts to create your admin account

### Step 6: Access Your Application

1. Your app will be available at: `https://gaayatri-app.onrender.com` (or your custom URL)
2. Admin panel: `https://gaayatri-app.onrender.com/admin/`
3. The `RENDER_EXTERNAL_HOSTNAME` environment variable is automatically set by Render

## Fast Deployment Option

If you want to **deploy quickly (2-3 minutes)** and skip the ML dependencies temporarily:

1. **Before deploying to Render**, switch to minimal requirements:
   ```bash
   mv requirements.txt requirements-full.txt
   mv requirements-minimal.txt requirements.txt
   git add .
   git commit -m "Use minimal requirements for fast deployment"
   git push
   ```

2. Deploy using the Blueprint method above
   - Build will complete in 2-3 minutes
   - All features work except semantic similarity filtering in chatbot

3. **To enable full ML features later**:
   ```bash
   mv requirements.txt requirements-minimal.txt
   mv requirements-full.txt requirements.txt
   git add .
   git commit -m "Switch to full requirements with ML"
   git push
   ```
   - Render will auto-redeploy with ML features (10-15 min build)

## Alternative: Manual Deployment

If you prefer not to use the Blueprint approach:

### 1. Create PostgreSQL Database

1. Click **"New +"** → **"PostgreSQL"**
2. Name: `gaayatri-db`
3. Choose free plan
4. Click **"Create Database"**
5. Note the **Internal Database URL**

### 2. Create Web Service

1. Click **"New +"** → **"Web Service"**
2. Connect your GitHub repository
3. Configure:
   - **Name**: `gaayatri-app`
   - **Environment**: Python 3
   - **Build Command**: 
     ```bash
     pip install -r requirements.txt && python manage.py migrate && python manage.py collectstatic --noinput
     ```
   - **Start Command**: 
     ```bash
     gunicorn gaayatri_project.wsgi:application --bind 0.0.0.0:$PORT
     ```
   - **Plan**: Free

4. Add environment variables (see Step 3 above)
5. In the `DATABASE_URL` variable, paste the Internal Database URL from your PostgreSQL database

## Troubleshooting

⚠️ **For detailed troubleshooting, see [RENDER_TROUBLESHOOTING.md](RENDER_TROUBLESHOOTING.md)**

### Common Issues

#### Build Fails or Times Out

**Issue**: Deployment fails with "deploy failed" or times out
- **Root Cause**: Large ML dependencies (torch ~800MB) take 10-15 minutes to build
- **Solution 1**: Be patient! First build can take 10-15 minutes. Don't cancel.
- **Solution 2**: Use `requirements-minimal.txt` for faster deployment (2-3 minutes)
- **Solution 3**: Upgrade to Render Starter plan ($7/month) for more resources
- **Details**: See [RENDER_TROUBLESHOOTING.md](RENDER_TROUBLESHOOTING.md)

#### Build Succeeds But Deploy Fails

**Issue**: "No module named 'PIL'" or similar
- **Solution**: Ensure `Pillow` is in `requirements.txt` (already included)

**Issue**: "System check identified issues"
- **Solution**: Check environment variables are set correctly

### App Crashes on Start

**Issue**: Database connection errors
- **Solution**: Verify `DATABASE_URL` is set correctly
- **Solution**: Ensure database migrations ran successfully

**Issue**: "SECRET_KEY not set"
- **Solution**: Render should auto-generate this. If not, add it manually in Environment tab

### Chatbot Not Working

**Issue**: Chatbot returns errors
- **Solution**: Verify `CHATBOT_API_KEY` or `GROQ_API_KEY` is set correctly
- **Solution**: Check your Groq API key is valid and has credits

### Static Files Not Loading

**Issue**: CSS/JS not loading (404 errors)
- **Solution**: Ensure `python manage.py collectstatic` ran in build command
- **Solution**: Check `whitenoise` is in `requirements.txt` (already included)

### Slow First Load

**Issue**: Application takes 30+ seconds on first request
- **Solution**: This is normal for free tier (cold starts)
- **Solution**: Consider upgrading to a paid plan for better performance
- **Solution**: PyTorch initialization can be slow on first load

## Updating Your Deployment

Render automatically deploys when you push to your repository:

1. Make changes locally
2. Commit and push to GitHub:
   ```bash
   git add .
   git commit -m "Your changes"
   git push origin main
   ```
3. Render will automatically detect the changes and redeploy

To disable auto-deploy:
1. Go to your service settings
2. Toggle **"Auto-Deploy"** off

## Database Backups

Free tier includes:
- Automatic daily backups (retained for 7 days)

## Cost Considerations

**Free Tier Limitations:**
- Web service: 750 hours/month (enough for one app)
- PostgreSQL: 256 MB storage
- Cold starts after 15 minutes of inactivity
- Shared CPU and 512 MB RAM

**Recommended Upgrades for Production:**
- Starter Plan ($7/month): Better performance, no cold starts
- Database upgrade: More storage and connections

## Security Best Practices

1. ✅ `DEBUG=False` (set by render.yaml)
2. ✅ Random `DJANGO_SECRET_KEY` (auto-generated by Render)
3. ✅ HTTPS enforced automatically by Render
4. ✅ Database credentials managed securely
5. ⚠️  Keep your `CHATBOT_API_KEY` secret - never commit to Git

## Quick Reference: Environment Variables

| Variable | Required | Description | Default |
|----------|----------|-------------|---------|
